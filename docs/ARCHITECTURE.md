# NOCTTY Architecture

Current verified boundary: 2026-07-18.

## Design

NOCTTY separates durable product state from volatile platform APIs.

- Zig product state owns configuration, themes, workspaces, tabs, panes, status, paste policy, projects, and recovery. NoctEd owns its documents and settings in a separate Zig process; the obsolete workspace editor model has been removed.
- Recovery is write-through at the product-state boundary. Workspace mutations target one atomic XDG-state hot-session snapshot, while GUI settings use their independent atomic config file. Startup validates and loads the snapshot before the GTK host allocates restored sessions.
- Pane selection and tags remain Zig-owned workspace state; the Smart Tab filter is a volatile view query over the same live pane IDs and never duplicates PTY/session ownership. A narrow ABI exposes de-duplicated borrowed tag names to native editable suggestion lists. The adapter hands focus to the first matching visible area when a filter hides the current focus and presents an ephemeral tag-named empty-state panel with button and zero-match `Escape` clear paths.
- Thin native adapters own GTK/Cairo widgets, Plasma GlobalAccel, Noctalia compositor plans, D-Bus activation, Wayland/X11 presentation, desktop notifications, native dialogs, clipboard exchange, and POSIX ABI calls.
- Ghostty symbols are confined to `src/ghostty`; no workspace, config, theme, editor, or host state depends on their layouts.

This boundary keeps the runtime native while preventing compositor, toolkit, and optional terminal-library churn from redefining product semantics.

## Terminal Pipeline

```text
shell process
    ↕
Zig PTY session
    ↕
Zig VT grid and scrollback
    ↕
TerminalSession
    ↕
thin GTK/Cairo adapter
```

- `src/terminal/Pty.zig` owns the complete PTY boundary: validated fixed-argv fork/exec setup, shell lifecycle, nonblocking descriptor I/O, resize, exit observation, process-group teardown, foreground metadata, and bounded Linux `/proc` resource sampling.
- `src/terminal/PaneInfo.zig` owns validation, CPU-delta calculation, and allocation-free formatting of active-pane/resource display and tooltip text. `Pty.zig` owns `tcgetpgrp`, process-group teardown, and all Linux `/proc` reads. It returns bounded NOCTTY-tree and selected-terminal-tree tick/RSS/process samples rather than leaking system paths or process APIs into GTK state.
- `src/terminal/Vt.zig` owns renderer-neutral cells, Unicode decoding, ANSI styles/colors, cursor and title state, scroll regions/history, alternate screen, editing modes, bracketed paste, focus, and mouse modes.
- `src/terminal/Session.zig` pumps PTY bytes into the grid and exposes stable input, resize, title, redraw, and lifecycle callbacks.
- `src/gui/native_grid_abi.h` and `src/gui/NativeGridAbi.zig` define and validate the size/version-checked ABI v2 callback and launch structures. `src/gui/native_grid_host.c` renders packed rows, dirty spans, rich cell styles, and the cursor with GTK/Cairo and maps native input/clipboard/focus/resize events back into the session. Each pane context is initialized explicitly with one root controller and narrowly borrowed immutable or shared state; pane creation never copies a live context containing owned pointers and GLib source IDs. `src/gui/NativeGtk.zig` owns the migrated compact GTK widget/style helpers, action-button affordances, tab lookup/color styling, settings-page composition, label/control accessibility relationships, visibility, and object-owned caches behind the retained native GTK header.

The session pump drains nonblocking reads through a reusable 128 KiB buffer until `EAGAIN`, EOF, or a 2 MiB per-pane dispatch. Each live native pane exposes only its PTY descriptor across the adapter and owns one `g_unix_fd_add_full` source. Read readiness performs one bounded pump per GLib dispatch; mapped output is coalesced onto one owned frame-clock callback, hidden output remains on the 100 ms path, and unmapped areas do not queue redraws. The continuous read tick is gone. The root maintenance pass polls descriptor-backed exit state once per second; a pane-local 16 ms read/exit fallback is created only if descriptor registration fails. One root-owned timer handles cursor blink and one handles pane status, descriptor exit safety, and app maintenance instead of duplicating those timers per pane. `stop_grid_io_sources` and `stop_grid_context_sources` provide the authoritative idempotent teardown path before session destruction across pane close, tab close, retirement, natural exit, application close, and final shutdown (`pty_pump_bounded_drain=true`, `pty_event_source=true`, `timer_read_polling=false`, `output_present_coalesced=true`, `frame_clock_present=true`, `hidden_present_throttled=true`, `mapped_redraw_only=true`, `root_timer_coalesced=true`, `event_source_cleanup=true`, `descriptor_fallback=root_coalesced`, `pane_exit_timers=0`, `source_cleanup=centralized`).

Active-pane identity and resource observation reuse that maintenance cadence rather than adding pane timers. Focus and notebook switches request an immediate cached refresh; steady-state command/resource transitions query only the focused page once per second. The Zig PTY module resolves the foreground process group, performs bounded `cwd`/`comm` reads, and samples the NOCTTY and selected shell process trees in one shared traversal when the pane is a descendant; the pure Zig formatter emits `short cwd : process | App CPU/RSS | Pane CPU/RSS` plus a detailed tooltip into caller-owned buffers, and the GTK component skips unchanged setter work. One root-owned strip is packed after the notebook, keeping bottom-positioned tabs above it while restore, preset rebuild, recursive split, and pane-move code operate only on page content (`pane_source=pty_proc`, `pane_refresh=coalesced`, `pane_info_dedup=true`).

Parent-window hide and final destruction first pop down the tracked workspace menu, the current GTK menu grab, and visible process-local `GTK_WINDOW_POPUP` toplevels. A pending GTK iteration completes those child unmaps before final parent destruction; the hot-session Wayland/X11 lane runs warning-fatal and reports `popup_teardown=true`.

The VT keeps the visible screen and a bounded hot history window as direct cells while cold logical lines use compact UTF-8 grapheme and style-run storage. Monotonic line IDs, grapheme-relative anchors, wrap metadata, and change generations preserve retained logical identity through primary-screen narrow/wide reflow; stale anchors fail deterministically after eviction. Full-screen scroll changes one visible-row origin and clears one row instead of moving the slab. Scrollback defaults to 1000 lines, is GUI-configurable from 0 through 100000, grows lazily from at most 32 rows, forces cold-arena compaction when reduced, and keeps cold storage memory-only. Alternate-screen resize is non-reflowing. The normal printable-ASCII path writes equivalent runs while control, ANSI, UTF-8, insert, and non-wrap input retains bounded table-driven parsing (`visible_grid_ring=true`, `vt_ascii_run=true`, `native_output_throughput=true`).

Every VT mutation records affected column spans. On output presentation the ABI v2 adapter consumes those spans once, queues bounded changed-cell regions, redraws old and new cursor cells when needed, and invalidates all rows when a pane first maps. Painting copies packed rows into reusable pane-owned storage, coalesces equal-background fills, and reuses guarded Cairo glyph conversions while retaining per-cell fallback for graphemes, fallback fonts, and rich style transitions (`render_abi=packed_rows`, `render_abi_version=2`, `damage_tracking=dirty_spans`, `glyph_batching=true`, `glyph_cache=true`). No presentation-time row hash remains.

The default executable follows this pipeline. `src/gui/VteHost.zig` and VTE are compiled only into the optional `noctty-vte` fallback. Production `noctty` does not link VTE or Tree-sitter and rejects fallback, smoke, and legacy-editor commands.

## Product State

- `src/app/App.zig` is the command boundary between adapters and durable state.
- `src/workspace` owns tabs and durable manual-title overrides, independent pane IDs, split/layout and ephemeral pane-zoom state, selection, broadcast targets, pane transfer, workspace quick notes, project rows, snapshots, autosave, and recovery.
- `src/config` validates GUI settings and persists versioned native snapshots atomically. Settings snapshot version 9 includes the active launch profile, bounded named library, selected identity, and bounded recent-workspace MRU while admitting tmux/Zellij kinds; version 8 preserves the same stored fields without those kinds, version 7 preserves launch state with an empty recent list, version 6 preserves its active profile with an empty launch library, and versions 1–5 remain importable.
- `src/terminal/LaunchProfile.zig` owns the fixed-capacity shell/command/cwd/environment/SSH/session model and validation. `src/terminal/Pty.zig` consumes only the validated launch kind and strings; SSH, tmux, and Zellij use fixed direct argv and launch choices do not enter workspace, theme, editor, or Ghostty adapter state. PTY teardown snapshots both shell and foreground process groups, tracks them independently through the bounded grace period, and forces either surviving group without leaking process control into workspace state.
- `src/theme` owns built-ins, Ghostty/Xresources/Alacritty import, selection, preview data, and native library persistence.
- `src/nocted` owns the standalone editor's bounded document loader, permission-preserving replacement and atomic first-save, immutable arena-backed project index with capped structural deltas and conservative fallback, streaming project search and capped coalesced fuzzy quick-open, at most two lazy worker lanes, GIO monitoring and external-change decisions, indentation-fold analysis, 100 ms-coalesced direct vendored Tree-sitter parsing below a 32 KiB/4,096-capture GTK-thread ceiling with complete GtkSourceView fallback, GUI settings, syntax discovery, bounded non-executing TextMate JSON-to-GtkSourceView conversion, native GTK/GtkSourceView surface, and declaration-only toolkit ABI.

Strings loaded from persistence are copied into Zig-owned storage. Adapters receive stable values or narrow callbacks; they do not own product state.

## NoctEd Process Boundary

`nocted` is built and installed beside `noctty`, but it is not a module loaded into the terminal process. `Open NoctEd Here` resolves the selected pane cwd and starts `nocted --project <cwd>` with `g_spawn_async`. GLib's normal child handling prevents zombies; NOCTTY retains no child handle and does not couple editor shutdown to terminal shutdown. Installed binaries resolve resources from `../share/nocted`; dependency-bundle binaries also resolve the `libexec/noctty` to `../../share/nocted` layout.

NoctEd's native surface is implemented in Zig. `src/nocted/gtk.zig` contains only the GTK 3, GDK, GLib-thread-pool, and GtkSourceView 4 declarations needed by that surface, isolating toolkit ABI details from document, project, search, quick-open, folding, settings, syntax-discovery, and grammar-conversion state. Each document owns one GtkSourceBuffer and view; its search context and source map are created lazily when shown. Canonical paths map directly to documents, notebook pages retain their document pointer, and active-document lookup does not scan the tab list. Project-tree, project-search, and quick-open views each own one explicit GtkTreeStore reference but store bounded entry/result IDs rather than a second full-path payload; activation resolves IDs through the retained project index. Runtime grammar activation replaces the GtkSource language manager and then re-detects open buffers; mutating an already-enumerated manager's search path is forbidden by GtkSourceView and is not used. `src/nocted/Session.zig` writes private atomic version-2 state with ordered clean tabs and bounded dirty saved/untitled UTF-8 snapshots, reads legacy version-1 saved paths, and coalesces edit-pause persistence. Application hot exit writes immediately and blocks on failure; individual dirty-tab close retains its Save/Discard/Cancel guard.

`src/nocted/Worker.zig` is the sole background execution boundary. At most two lazy single-thread GLib pools accept no more than 64 outstanding jobs: foreground document, language-service, and project-task work plus background scan/search/index-delta work. Obsolete generations cancel before admission, worker loops advance bounded scanner/search steps, and immutable request data is copied before submission. Completions return through the GLib main context, where GTK state alone is published. Project scans produce an immutable arena-backed index; GTK builds a staging tree in bounded main-thread slices and swaps only after success. Coalesced create/delete/move/rename batches are capped at 256 and rebuild a replacement immutable index from the retained snapshot plus only the precise changed disk paths/subtrees. Save As submits that path directly. Ignore-control changes, malformed paths, unknown events, and overflow route back to the full scanner instead of guessing. Find in Files searches unsaved snapshots first, then advances disk work through reusable chunks and publishes immutable batches of at most 24 results or 25 ms with a two-batch UI cap. Quick Open uses smart-case gating and bounded path-aware top-K ranking. Content-only `GFileMonitor` events drive clean-reload/dirty-keep choices. Shutdown marks jobs cancelled, joins both lanes, drains completion ownership, removes monitors and pending owned event paths, and only then releases document/model/widget state (`nocted_worker=bounded`, `nocted_worker_lanes=2`).

Folding uses a single-pass indentation analyzer capped at 4096 regions and depth 256. The UI applies a scaled invisible GtkTextTag to non-overlapping bodies and tracks ranges with live marks; it never removes or duplicates document text, never enters the undo manager, and never changes modified state. Save reads the complete buffer unchanged; edits, search, undo/redo, and disable-folding remove tags before operating. Find in Files caps a query at 256 bytes and a scan at 1024 files, 1 MiB per file, 32 MiB total, 1000 matching lines, and 240 UTF-8 preview bytes. Search results are not retained outside the GTK model after the bounded core result is released.

The normal path is proved in two parts: the NOCTTY handoff receipt requires `editor_binary=nocted editor_handoff=true directory_resolved=true editor_process_separate=true`, and NoctEd's own warning-fatal rendered receipt requires `project_activation=true minimap_overlay_translucent=true editor_zoom=true search=true find_in_files=true project_search_activation=true multi_file_tabs=true tab_navigation=true close_other=true close_all=true untitled=true save_as=true save_as_collision=true quick_open=true quick_open_bounded=true quick_open_activation=true session_dirty_restore=true hot_exit=true code_folding=true folded_save=true atomic_save=true permissions_preserved=true zig_syntax=true rendered=true`. See [NOCTED.md](NOCTED.md) for syntax compatibility and the maturity boundary.

## Optimization Roadmap

The source-backed [performance and algorithm research](PERFORMANCE_ALGORITHM_RESEARCH.md) audits the terminal renderer, VT storage/parser, NoctEd index, filesystem worker, project search, and quick-open paths against primary upstream implementations and API contracts. Its lower-complexity designs are implemented while preserving ownership: GTK frame-clock presentation and reusable Cairo glyph storage, bounded terminal protocol/state and logical-line storage, an immutable arena-backed worktree snapshot with a GIO monitor adapter, and at most two lazy single-thread filesystem lanes with bounded streaming publication. The existing GTK/Cairo renderer and GtkSourceView text surface remain authoritative.

GPU rendering, dedicated read/write/render thread sets per pane, a second rope or piece-tree text model, required external search executables, and runtime-downloaded grammars remain deferred. Any `libghostty`, GIO monitor, or parser integration stays behind an adapter and may not leak its types into configuration, workspace, theme, or editor state. NCT-120 and NCT-110's bounded deterministic protocol/state plus malformed/Unicode tranche have completed their qualifications; NCT-110 now also retains a real installed Codex login/Vim/btop headless PTY/VT tranche, but still needs authenticated/broader real-agent cross-backend acceptance. NCT-112 retains bounded allocator-accounted real-PTY repetition, HUP-resistant foreground-group shutdown, and one controlled installed-application sequence per mode, but still needs multi-day native hidden/visible and sustained authenticated-agent output evidence. NCT-119 retains exact display-independent production-Cairo repeat pixels, draw process-CPU percentiles, renderer-owned warm/resize allocation counts, and root memory, but still needs archived compositor-backed pixels, full-stack allocation/idle-wakeup evidence, and mapped PTY/input/frame-clock latency distributions. NCT-121 retains synthetic 4K/25K/100K scan/delta/model-memory plus bounded X11/Wayland current-project model/tree-draw, actual monitor-burst publication, overflow-recovery, and post-widget callback evidence. NCT-122 additionally retains the real headless two-pool GLib worker/backpressure/foreground-save seam and two eight-cycle native Wayland Debug runs through GTK publication and draw. NCT-121/NCT-122 still require sustained project lifecycle plus matching `ReleaseSafe`/X11 search-load, process-tree-memory, and long-duration evidence specified by the audit (`performance_algorithm_research=true`).

## Native Host

The default host supports an undecorated dropdown, borderless windowed, and zen-fullscreen modes. Dropdown width changes always recompute symmetric monitor margins, undersized legacy pixel overrides fall back to the configured percentage above a 480×240 floor, and windowed startup reapplies a bounded 80%×75% work-area size. A GTK notebook plus recursively nested split containers render on-demand independent sessions; every split is positioned at the source pane midpoint so newly created panes remain visible. Settings remains an owned native dialog rather than application state: GTK transient/destroy/keep-above hints cover X11 and ordinary Wayland toplevels. When the parent is a Wayland layer-shell overlay, the adapter creates Settings as a separate overlay layer surface, temporarily moves the parent to the top layer, and restores the parent overlay in the dialog destroy callback. Mouse press claims GTK focus for that exact drawing area and synchronizes the active Zig pane before keyboard input, context menus, and native drag/drop route changes through `App.dispatch`. Split Down creates a vertical top/bottom container, while Split Left creates a horizontal container with the new pane on the left.

Drop-down focus-loss hiding is popup-aware. Window focus-out schedules a bounded recheck instead of hiding immediately; a tracked GTK context menu/grab keeps the parent mapped, and menu destruction schedules the final check after GTK can restore focus or present an owned transient. The hide decision also requires logical `window_presented` state, so an explicit F10/D-Bus hide cannot be reversed during its reveal animation.

The obsolete embedded editor and its duplicate document model have been removed. Standalone NoctEd owns editor buffers, syntax, save prompts, and lifetime; NOCTTY owns only the cwd-based process handoff. NOCTTY close preflight therefore covers foreground terminal processes only.

Selection ownership separates a persistent completed range from the transient Button-1 drag state. Plain clicks clear the range, release ends dragging, focus loss cancels dragging, and pointer motion without Button 1 cannot mutate a selection. Double-click pane zoom clears both states and arms a one-release suppression token before changing geometry; the trailing release is consumed rather than reinterpreted at resized coordinates, while a later normal press or focus loss clears any stale token.

Grid reads validate the current Zig dimensions at the C ABI. If GTK paints one stale allocation frame during a pane reparent/resize, the renderer receives blank default cells instead of indexing beyond the resized grid.

The same accepted `size-allocate` transaction updates a per-surface resize OSD state machine. A short arm delay suppresses creation layout; later changes store the exact grid columns/rows, queue a Cairo overlay draw, coalesce continuous movement by replacing one 750 ms hide timer, and repaint cleanly when it expires. No workspace state or terminal-library ABI depends on this adapter-only feedback.

Terminal font scaling has separate local and global transactions. Ctrl+wheel is consumed before the existing scrollback/application-mouse branches, accumulates smooth deltas per surface, clamps against Zig-provided limits, updates only the target GTK context, and recomputes that pane's font-derived cell geometry before resizing its PTY. The resulting hundredth-point event is validated into the Zig-owned pane profile and persists through workspace snapshots. Settings retains the global default path and can apply one size across current contexts without changing Ctrl+wheel isolation.

Profile presets use that same pane-owned boundary. Zig defines Global default, Compact, Readable, High contrast, and Mono no ligatures and resolves the selected preset into family, point size, theme/contrast, and ligature preference. The terminal context menu stores the right-clicked pane on its `Profile` submenu; choosing an item dispatches that exact pane ID, and Settings labels the same selector `Active pane profile`. A narrow read ABI returns the current preset plus its resolved fields so GTK can synchronize only that pane, recalculate its Cairo cell geometry/PTY dimensions when size changes, and repaint high-contrast state without mutating a neighbor. Snapshot/autosave restore remains Zig-owned. The ligature boolean is live adapter state and persists, but the present renderer paints one codepoint per fixed Cairo cell and does not expose a Cairo font-feature shaping switch. The Mono no ligatures receipt therefore proves state delivery and isolation, not shaped-ligature suppression or broader typography parity.

Pane movement updates the Zig workspace first, collapses the source GTK split, reparents the same drawing area/session into the destination page, rebuilds the destination split, switches pages, and restores focus. Moving a tab's last pane closes the now-empty source tab. Tab-position changes apply directly to the live notebook and are queried from loaded Zig configuration during host creation. Double-clicking the native tab-label event target hides that label and embeds a borderless `GtkEntry` in the same tab box. Enter dispatches a bounded UTF-8 title through `App`, sets the Zig manual-override bit, marks recovery dirty, redraws the compact label, and restores terminal focus; Escape or focus moving to another widget destroys the entry and redraws from unchanged model state. No rename toplevel or modal loop exists.

Tab-label right-click uses the page stored on that exact event target. The same stable page/pane lookup routes both `Tab Color` and `Close Tab`, so a background tab receives its own preset without activating or recoloring the current tab. Accent preset plus bounded shade live on `Workspace.Tab`; GTK asks through a narrow packed-RGB ABI, derives readable title/close contrast, and never mutates terminal-theme state. Color commands mark recovery dirty and snapshot version 5 appends optional accent records after the older payload, preserving imports from versions 1–4. Before `Workspace.closeTab` mutates the model, every pane on that page is checked for a foreground process group and production defaults to `Keep Open` if any are busy. After acceptance, the host marks every affected context as retiring before IM focus or GTK hierarchy teardown, cancels each pane-owned descriptor, presentation, resize, and feedback source, deinitializes the complete PTY plus VT grid, and removes dynamic sessions from their pool immediately. All draw, focus, key, mouse, scroll, resize, PTY, drag, and clipboard entries share a live-session predicate; pending asynchronous clipboard delivery holds the small C context, not its released Zig session, until the callback drains (`foreground_guard=true`, `session_storage_released=true`, `late_callback_guard=true`). The root controller stays allocated when tab 1 closes; global show, resize, Settings, and the notebook's leading New Tab action resolve the current surviving page while the root maintenance/control/tray sources remain valid. Retired peers are severed so later `+` activation must allocate a fresh session rather than reuse a closed PTY.

Tab drag ordering is a GTK view transaction over stable Zig tab IDs. All initial, dynamic, and restored notebook pages are reorderable but nondetachable. The adapter snapshots the active page before pointer selection can activate a background tab, applies each `page-reordered` destination to `Workspace.reorderTab`, restores the prior active page, and queries Zig's model index to roll GTK back if dispatch fails. Drag motion marks recovery dirty but snapshot I/O is coalesced through the same 120 ms flush used by divider movement; hot-session reconstruction suppresses the callback so startup does not rewrite an unchanged workspace (`tab_reorder_pointer_drag=true`, `tab_reorder_active_identity=true`, `tab_reorder_rollback=true`, `tab_reorder_persistence_coalesced=true`).

Pane-context `Close Terminal` performs the same foreground-process preflight before the model-first boundary. `SplitLayout.removePane` recursively copies only the reachable survivor tree, collapses the removed leaf's parent to its sibling, and preserves surviving axes and divider ratios without serializing orphan nodes. `Workspace.closePane` selects a stable survivor, closes an emptied tab only when another tab exists, and rejects the application's final terminal. GTK then cancels the exact context's sources, deinitializes and releases its terminal session, collapses the corresponding `GtkPaned`, retains root-controller ownership when pane 1 was removed, and restores focus to the model-selected pane. Accepted PTY shutdown sends `SIGHUP` to the foreground and shell process groups, tracks both for the bounded grace period even when the shell exits first, and forces every remaining group so close cannot block the GUI or orphan a stubborn job (`pty_close_bounded=true`, `forced_group_shutdown=true`).

Layout presets use a bounded reconciliation transaction instead of the former fire-and-forget model event. The native host activates the clicked pane, grows real session contexts to 1/4/8/9/16, and then asks Zig to canonicalize and return the active tab's ordered pane IDs. Shrinking defaults to Cancel; acceptance moves every surplus live session to a new overflow tab before rebuilding, so no preset action closes a PTY. Only the selected notebook page is reparented into a row-major `GtkPaned` tree. Zig snapshot topology and GTK dividers use proportional one-over-remaining ratios, giving balanced 4×2, 3×3, and 4×4 layouts while leaving existing tabs and the root controller untouched. The allocation adapter keeps each dense pane's requested font as the persisted source of truth while deriving a temporary effective size that targets an 80×24 PTY floor; a transient zoom/grid OSD reports the reduction and normal growth restores the requested size.

Compact-power controls are overlay-first. A fuzzy command palette routes existing actions, including Smart Tab filtering and selected-pane tag management, scrollback search updates the Zig viewport and transient selection, quick notes write through `App.dispatch` into versioned workspace snapshots, and pane zoom is mirrored in Zig while GTK hides/restores sibling areas. Pure Alt press reads that one workspace note through the existing text-action ABI, validates and bounds it, then asks every mapped drawing area to paint a compact Pango tooltip; Alt release, top-level focus loss, and explicit dropdown hide clear the root-owned preview and redraw the same mapped set. Geometry-aware Alt+Arrow focus uses live pane allocations and then synchronizes the stable pane ID without suppressing the preview held by Alt. `Ctrl+Tab` and Alt+wheel share the active page's visible native-context traversal set, preventing hidden Smart Tab or zoom siblings from becoming input targets. Alt+wheel smooth deltas accumulate into bounded whole steps; down advances and up reverses through that set, normal GTK focus synchronizes the stable Zig pane ID, and the target paints an 800 ms blue frame plus `Pane n / total` chip without mutating the separate tag-selection group. `Ctrl+Shift+Tab` and Ctrl+Alt+wheel switch GTK notebook pages through the same focus and Smart Tab application path without mutating the Zig-owned tag. Ctrl+Alt+wheel has a separate root accumulator; down advances, up reverses, both wrap, and each accepted step paints an 800 ms purple frame plus `Tab n / total` chip over the focused terminal. BEL serials become tiny rolled-up tab attention dots. GTK IM composition commits UTF-8 through the same PTY write boundary.

Terminal control chords have a narrower routing contract than ordinary input. Plain `Ctrl+C` bypasses `deliver_grid_input` and writes one ETX directly to the focused context, preventing broadcast mode from multiplying an interrupt; `Ctrl+Shift+C` remains clipboard copy. Plain `Ctrl+D` is consumed before terminal encoding and enters `close_grid_pane`, so Zig accepts exact-pane removal before PTY/timer teardown and GTK split collapse. No EOT is written. A rejected final-pane close is still consumed, preserving the one-terminal invariant without changing shell state.

The context-menu `Open NoctEd Here` action asks the selected PTY session for `/proc/<pid>/cwd` with workspace-pane fallback, resolves the sibling `nocted` binary through `/proc/self/exe` or `PATH`, and starts the standalone process at that directory. A native error dialog reports missing or failed launches. NOCTTY retains no editor buffer or child-lifetime state.

The compact tab row remains visible with one or more tabs so its leading themed New Tab action is always available; pane zoom temporarily hides the whole row and restores it on exit. GTK positions New Tab at the notebook's start edge and a flat system-theme control group at the end edge, with Settings immediately before Close as in Yakuake. A notebook-scoped application-priority style removes theme-inflated header/tab margins and borders; tab labels stop at 18 visible characters, multi-pane state contracts to `×N`, and New Tab, Settings, application Close, and per-tab Close retain compact 24-logical-pixel minimum targets. These actions use GTK symbolic icons rather than font-dependent Unicode glyphs. A widget-scoped provider may layer the resolved tab accent onto that compact content only; switching pages re-resolves active styling, while Default removes the provider and returns to the system theme. The group changes orientation with top/bottom versus left/right tab placement. A shared native action-button helper preserves explicit tooltip copy, derives a label fallback when needed, applies the portable named `default` cursor during hover, and restores inherited pointer semantics on leave. Settings reuses the native dialog, while Close and tray Close enter the same foreground-process preflight before idempotent all-session teardown without conflating their activation receipts. Every title can still be renamed in place without a separate toolbar. Shell OSC titles remain live until a manual title override is stored in the versioned workspace snapshot. Drop-down width, height, reveal duration, focus-loss hiding, optional pointer focus, active-pane information visibility, and the four-pixel bottom resize grip are settings-backed. The information strip is one root-level bottom row below the notebook; split panes do not receive individual title bars and no permanent sidebar is added.

Plasma GlobalAccel registration is availability-checked and accepted-key verified. Hidden dropdown startup is permitted only after registration succeeds. A conflict or transport failure leaves the window visible. The key recorder uses the same path and persists only a successful registration.

Noctalia-compatible Wayland uses the shell's documented ownership split. The compositor binds F10 to `noctty --toggle`; the host owns `com.noctty.NOCTTY` and exposes native D-Bus status/show/hide/toggle methods. `noctty --hidden` hides only after that endpoint is ready, while an ordinary launch remains visible. The same recorder persists the shortcut into Zig config, and `--noctalia-plan` serializes its current value for Niri, Hyprland, Sway, Scroll, Labwc, or MangoWC. `src/gui/Noctalia.zig` contains this isolated compatibility model.

On X11, dropdown geometry is horizontally centered and read back against the monitor work area. On Wayland, GTK layer-shell uses the `noctty-dropdown` namespace, overlay layer, recomputed symmetric width margins, top anchoring, and no exclusive zone. Runtime loading uses only the `libgtk-layer-shell.so.0` system soname. Distribution packages provide that runtime, while dependency bundles and dogfood installs expose their private architecture-local copy through a launcher-owned library path; the vendored x86_64 payload is not loaded from the caller environment or current directory.

Status borders/tooltips (including Zig-owned pane tags, selection groups, and broadcast state), freedesktop notification delivery, GTK clipboard exchange, settings/theme/project dialogs, the NoctEd process handoff, and the GLib maintenance timer are live consumers of the Zig command model.

## Ghostty Decision

The installed public development package and pinned upstream commit `53bd14f` expose VT utilities but no supported Linux GUI platform-surface ABI. A private package-owned `libghostty.so` is rejected because its header, struct layout, callbacks, and compatibility contract are not public.

NOCTTY therefore:

- maintains no Ghostty fork;
- uses its Zig PTY/VT renderer as the supported Linux implementation;
- optionally dispatches the published `libghostty-vt` paste utility;
- retains isolated probes and fake-symbol lifecycle tests for a future supported ABI;
- makes no Ghostty-rendering claim.

A future public Linux surface can replace only the isolated adapter after version/layout rejection and live lifecycle proof; it does not require changes to product state.

## Persistence and Privacy

Settings, themes, syntax-theme selection, workspaces, autosaves, and recovery files use versioned native formats and atomic writes under XDG-style paths. Workspace snapshot version 6 includes the Smart Tab tag alongside tabs, panes, recursive split nodes and ratios, active identities, titles, accents, selection/tags, visual profiles, notes, broadcast state, and working directories; workspace versions 1–5 remain importable. Independently, settings snapshot version 9 stores one active launch profile, up to eight named shell/command/SSH/tmux/Zellij profiles with selected identity, and up to eight validated absolute recent-workspace paths. Every name, nested profile, and MRU path is fixed-capacity native state. Version 8 imports the launch/recent state but rejects the new continuity kind values, version 7 imports launch state with an empty recent list, version 6 imports active launch fields with an empty launch library, and versions 1–5 import the default interactive-shell profile. The GTK forms send complete validated transactions. Fresh workspaces and newly created tabs/splits use the active profile, while hot-session or explicit workspace reconstruction retains each saved pane cwd and starts a fresh shell rather than replaying a later launch command. The SSH adapter remains a direct validated target passed to the system client; its bounded acceptance harness supplies isolated options outside production, then proves disposable Ed25519 public-key authentication through the real client/server and product PTY (`credentialed_ssh=true`). The tmux/Zellij adapter likewise uses fixed argv with a conservative session name; its retained shim qualification proves dispatch but not installed live reattach. URI admission accepts only local `noctty` and `file` forms and validates the decoded path before snapshot I/O. Restore validation rejects malformed topology before replacing startup state. The GTK adapter queries the validated tree and recreates native pages, `GtkPaned` nodes, and one fresh PTY per saved pane without imposing the historical 8/9-pane smoke limits. Explicit open/recent activation starts a separate native process so it does not replace PTYs in the current window. The installed-activation harness observes mapped/drawn state only in the smoke build while exercising the unchanged production desktop resource and `--open-uri`/`--open-workspace` entry points; no receipt hook enters the production binary. OS process memory cannot be resurrected. Users configure state through the GUI. There is no telemetry, analytics, crash upload, update ping, remote feature flag, browser runtime, credential store, or network service.
