# Compact Power UX

Last verified: 2026-08-05.

NOCTTY adapts the strongest low-chrome interactions from [Wave Terminal](https://docs.waveterm.dev/releasenotes), [PrettyMux](https://prettymux.com/), and [Yakuake](https://apps.kde.org/yakuake/) without copying their implementation or turning the terminal into a dashboard.

## Default Shortcuts

- `Ctrl+Shift+P`: command palette
- `Ctrl+Shift+F`: find across the active terminal grid and scrollback
- `Ctrl+Shift+N`: workspace quick note
- `Ctrl+Shift+G`: set or clear the Smart Tab filter
- `Ctrl+Tab`: cycle forward through visible panes on the current tab
- `Ctrl+Shift+Tab`: cycle forward through ordinary and Smart Tab-filtered tab views
- `Ctrl+Shift+Y`: tag selected panes
- `Ctrl+Shift+Z`: zoom or restore the active pane
- `Ctrl+Shift+R`: rename the active tab
- `Ctrl+Alt+=`: lighten the active tab color
- `Ctrl+Alt+-`: darken the active tab color
- Hold `Alt`: show the workspace note in every visible pane
- `Alt+Arrow`: focus the nearest pane in that direction
- `Alt+wheel up/down`: previous or next visible pane on this tab
- `Ctrl+Alt+wheel up/down`: previous or next tab / Smart Tab view
- `Ctrl+Shift+K`: compact shortcut card
- `Ctrl+wheel up/down`: increase or decrease the pointed pane's font size
- `Ctrl+C`: interrupt only the active terminal pane
- `Ctrl+D`: close the active terminal pane; protect the final pane
- `Ctrl+S`: save the current NoctEd document
- `F10`: show or hide NOCTTY

Inside the separate NoctEd window:

- `Ctrl+N`: create a clean untitled buffer
- `Ctrl+S`, `Ctrl+Shift+S`: save or open native Save As
- `Ctrl+P`: fuzzy-filter the bounded project file index and open the selected path
- `Ctrl+F`, `F3`, `Shift+F3`: find in the current file and move between matches
- `Ctrl+Shift+F`: open Find in Files; Enter starts the bounded asynchronous project search
- `Ctrl+PageUp`, `Ctrl+PageDown`: previous or next file tab
- `Ctrl+W`: close the current file through Save/Discard/Cancel
- `Ctrl+Shift+[`, `Ctrl+Shift+]`: fold or unfold the current indentation region

`Ctrl+Tab` wraps within the current GTK page and skips panes hidden by a Smart Tab filter or pane zoom before synchronizing the stable pane ID in Zig. Alt+wheel uses the same visible current-page order: down advances, up reverses, and smooth deltas accumulate into whole steps. Each pane target receives an 800 ms blue focus frame and `Pane n / total` chip without changing the tag-selection group or consuming layout space. `Ctrl+Shift+Tab` advances the notebook without clearing the active tag, so filtered tab views remain in the same navigation loop. Ctrl+Alt+wheel uses that tab loop with down for next and up for previous, wraparound, separately accumulated smooth steps, and an 800 ms purple `Tab n / total` overlay over the focused terminal. `Ctrl+Shift+B`, the command palette, and the pane menu share one explicit broadcast-input path: enabling explains selected-versus-all-tab targeting and defaults to `Keep Off`; disabling is immediate. Existing `Ctrl+PageUp`/`Ctrl+PageDown`, split, copy/paste, and pane-selection shortcuts remain unchanged. F10 uses GlobalAccel on Plasma and `noctty --toggle` from the compositor on Noctalia; both target the same compact reveal behavior.

Plain `Ctrl+C` is terminal-local even when broadcast is on: one ETX is written directly to the active pane and never duplicated to selected or neighboring panes. `Ctrl+Shift+C` remains copy. Plain `Ctrl+D` is a workspace close chord rather than terminal EOF; it reuses `Close Terminal` foreground-process confirmation plus model/session/GTK teardown and focus handoff without forwarding EOT. The final pane is protected and receives neither close nor EOT.

Holding either Alt key reads the existing persisted workspace quick note and paints it in the upper-right corner of every mapped terminal pane. UTF-8 and multiline text wraps to at most three lines inside a 320×92-logical-pixel translucent tooltip; releasing Alt, hiding NOCTTY, or moving focus outside the window removes every copy. Smart Tab- and zoom-hidden panes are not drawn. `Alt+Arrow` keeps its directional-focus behavior while the note remains visible for the duration of the chord.

Double-click a terminal pane to zoom or restore it. The gesture consumes its trailing release after the layout changes, so it cannot create a selection; ordinary Button-1 drag selection remains unchanged.

Right-click and choose `Open NoctEd Here` to launch the standalone editor at that pane's live cwd. The terminal context menu remains focus-safe through activation, then NOCTTY releases the popup and retains no editor child handle. NoctEd presents the compact left project tree, tabs, translucent right minimap, and source view in its own native window. At most two lazy bounded lanes separate foreground document load/save/path resolution from project scan/search and capped structural index deltas; precise create/delete/move/rename paths refresh on the scan lane, conservative fallbacks use the full scanner, and GTK builds the replacement staging tree in bounded main-thread slices while the prior tree stays usable. Find in Files appears only while invoked, publishes completed bounded results on the main thread, and opens a selected result at its line. `Ctrl+P` uses the already-pruned project index for a capped fuzzy file list and coalesces query edits before filtering. Folding compacts hidden lines with zero-copy tags, leaves the full buffer and undo history intact, and unfolds before edits or search. `Ctrl+N` creates an untitled buffer; `Ctrl+S` uses permission-preserving atomic replacement or routes its first save through the native chooser, while `Ctrl+Shift+S` always opens Save As. Closing a dirty NoctEd document or window, including close-other/close-all, requires Save, Discard, or Cancel. Closing NOCTTY does not close NoctEd or discard its buffers.

Right-click a terminal pane and choose `Close Terminal` to stop and remove that exact session. A foreground command or agent produces a native `Keep Open` / `Close Anyway` warning before the workspace changes; accepted close has a bounded process-group shutdown and releases the complete PTY, grid, and dynamic session storage. The context is marked callback-retired before IM or GTK hierarchy changes, preventing a late focus, draw, input, resize, PTY, drag, or clipboard callback from reaching released session state (`late_callback_guard=true`). The sibling expands into the vacated split without flattening the saved split topology, focus moves to the model-selected survivor, and closing pane 1 does not retire the root window controller. A sole-pane tab closes only when another tab can survive; the application's final terminal remains protected.

Before the dropdown hides or shuts down, tracked menus, active menu grabs, and visible process-local GTK popup windows are dismissed ahead of the parent window (`popup_teardown=true`).

Choose `Layout 2×2`, `Layout 4×2`, or `Layout 3×3` from that same pane menu to materialize four, eight, or nine real native sessions on the clicked tab. New PTYs are allocated on demand, existing sessions are preserved, and balanced horizontal/vertical dividers create equal cells. `Layout 1×1` closes the surplus sessions through the normal pane teardown path and focuses the survivor.

Dragging a split divider, the full pane-information bar, or a three-pixel cardinal window edge shows each affected terminal's live grid as `columns × rows`. Terminal content keeps the text cursor, the information bar uses the north/south resize cursor, side targets use east/west resize, and no diagonal corner cursors are exposed. Pages with at least four panes automatically reduce their effective font to target the conventional 80×24 TUI floor, without overwriting the pane's requested/persisted font; growth restores it. If the bounded 3 pt minimum still cannot fit 80×24, the same OSD says `Min 3pt · columns × rows`; otherwise it briefly shows `Zoom N% · columns × rows`. Ordinary initial layout remains suppressed, and the OSD disappears 750 ms after the last accepted resize.

Tab, pane, and divider customization is also a hot-session transaction. Accepted workspace actions write through to the atomic recovery snapshot; continuous divider movement updates the matching Zig split node and coalesces the disk flush. On the next launch—even after an unclean exit—the native notebook, recursive ratios, active focus, titles/colors, tags and Smart Tab, pane profiles, notes, broadcast state, and cwd are reconstructed before the window appears. Settings use their own immediate atomic config path. Shells restart in the saved directories rather than claiming process-memory resurrection.

Holding Ctrl while scrolling changes only the pane under the pointer by one point per wheel notch. Smooth events accumulate independently per pane; the configured minimum/maximum are respected, neighboring panes retain their sizes, and only the targeted PTY/grid is resized to its new font-derived cell geometry. The pane profile persists through workspace save/load. Without Ctrl, wheel input keeps its existing scrollback or application mouse-reporting route; Settings remains the global default control.

Right-clicking a terminal exposes `Profile` without adding permanent pane chrome. Its five radio choices—Global default, Compact, Readable, High contrast, and Mono no ligatures—are resolved and applied by Zig for that exact pane; another focused or neighboring terminal is not a fallback target. Family, point size, high-contrast state, ligature preference, and the current preset synchronize into the live pane, and Settings presents the same selector as `Active pane profile`. Preset changes dirty and persist the workspace and restore with the hot session. Mono no ligatures records and restores the preference, but the current fixed-cell Cairo codepoint renderer does not claim font-feature shaping or visible ligature suppression.

Tabs use numbered defaults (`Tab 1`, `Tab 2`, `Tab 3`, …), live shell titles when available, and the working-directory basename when no shell title exists. Long titles use an ellipsis in the compact row while the full title remains in the tooltip. Double-click a visible tab title and its label becomes a selected borderless entry in the same tab. Enter commits through the Zig workspace model; Esc or clicking any other element cancels and restores the prior label. No rename popup or confirmation button is used. Manual names persist in workspace snapshots and take precedence over changing shell titles.

The workspace owns one compact information strip below the notebook, keeping bottom-positioned tabs immediately above the Yakuake-style information bar. For local sessions it keeps Konsole's default `%d : %n` shape, the final cwd component and foreground process, then adds `App` and `Pane` CPU/RSS summaries. `App` is the NOCTTY process tree; `Pane` is the selected terminal shell tree. NOCTTY obtains the process-group leader with `tcgetpgrp`, reads bounded `/proc` metadata, and samples descendant CPU ticks/RSS once per existing one-second root maintenance cadence. Rapid focus/draw refreshes reuse the last sample, so the bar adds no pane-local timer and unchanged GTK setters remain suppressed. Hover exposes pane ID, foreground PID, full directory, process, both process counts, CPU, and MiB values. Appearance > Client chrome can hide the strip and config snapshot v4 preserves that choice. CPU is a local Linux process-tree observation, not telemetry or a benchmark claim. A focused host-local microcheck over a five-process tree measured 200 sampler calls at 39.8 µs average; the UI samples two trees once per second, but that one-host observation is not a universal budget. SSH username/host expansion remains launch-profile work.

Right-click a tab title and open `Tab Color` to choose Default, Red, Orange, Yellow, Green, Cyan, Blue, Purple, or Pink for that exact page. The compact tab receives the resolved RGB while its label and close glyph automatically choose dark or light contrast; terminal palettes remain untouched. Choosing a preset resets its shade. `Ctrl+Alt+=` and `Ctrl+Alt+-` then move the active tab through four reversible lighter/darker steps, and start an uncolored tab from Blue. The same actions are searchable in the command palette. Preset and shade mark the workspace dirty and persist in version-5 snapshots with older-file compatibility.


`Rename active tab` is also available in the command palette and via `Ctrl+Shift+R`.

The persistent `+` New Tab button exposes `Ctrl+Shift+T` in its tooltip and accessibility name.

Settings and Close occupy the tab row's far edge in Yakuake's order, with Settings immediately before Close. The compact strip keeps visible titles to 18 characters and uses `×N` instead of wider multi-pane text while tooltips retain full detail. New Tab, Settings, application Close, and per-tab Close use GTK symbolic icons and 28-logical-pixel minimum targets. The controls follow horizontal or vertical tab placement, expose accessible names and tooltips, and now share explicit hover, active, and keyboard-focus states. As with every native action button, hover uses the desktop's standard arrow pointer and a concise native tooltip, then restores the surrounding surface's cursor on leave. Settings opens NOCTTY's work-area-bounded native configuration window; owned dialogs stay above the dropdown on Plasma Wayland, and the window advertises the installed `com.noctty.NOCTTY` icon instead of a generic Wayland mark. Close stops all active PTYs and timers before leaving the application.

Attention and unsaved-workspace markers appear beside the title without replacing it. Attention clears when the pane receives focus or its session exits; the unsaved marker follows workspace save state.

Click the leading `+` icon before the first tab to create and focus a new native tab. The row remains visible in a one-tab workspace, and the action resolves the current notebook page; after the original host tab is closed it allocates a fresh Zig session instead of reusing the retired PTY.

Click a tab's close button or right-click its title and choose `Close Tab` to close that exact page, even when another tab is active. The last tab remains available; an accepted close stops the page's PTYs and pane timers, keeps the compact one-tab row and `+` action available, and sends focus back to the surviving session.

The native Settings window follows Yakuake's compact list pattern: Window, Behavior, and Appearance remain keyboard-selectable in a narrow system-icon sidebar while only the active page is shown. Category rows have explicit accessible names, 48-logical-pixel targets, destination-specific tooltips, selected-state contrast, visible keyboard focus, and opening Settings places focus on Window so keyboard users can navigate immediately. Both axes remain scroll-accessible on narrow work areas instead of clipping launch-profile controls. Existing settings continue to apply live and persist through the Zig configuration boundary.

Transient power surfaces are named at their actual controls: command search and results, terminal search and result status, and Quick Note text plus save status. The compact smoke reads those ATK names before accepting the interaction path.

## Chrome Budget

- One or more tabs use one compact row with a leading `+` New Tab action, short double-click-renamable/right-click-colorable/closable titles, one status/attention dot, and trailing Settings then Close app actions.
- Terminal close reuses the transient pane menu and existing split; it adds no per-pane close button or title bar.
- Pane status remains a one-pixel border plus tooltip. At most one optional 18-pixel information row exists per tab page; split panes do not each gain a title bar.
- Search, command, note, shortcut, settings, theme, and project surfaces are transient.
- Hold-Alt note previews are painted into visible terminal surfaces, reserve no layout space, and disappear on release or window focus loss.
- Resize dimensions are painted over the terminal only while resizing and reserve no layout space.
- Font scaling reuses the terminal surface and transient resize dimensions; it adds no toolbar or status row.
- Borderless resize targets use only the outer six pixels and add no title bar; the tray icon preserves one-click access while hidden and keeps Show/Hide, Settings, and foreground-process-aware `Close NOCTTY` in a transient desktop-rendered menu.
- Zoom temporarily hides sibling panes and the tab row, including `+`, then restores the exact live sessions and creation action.

Wave web widgets, embedded AI services, and browser blocks are intentionally not imported because NOCTTY has no browser runtime or remote service. PrettyMux's persistent project sidebar is represented by transient palette/project surfaces instead. Ghostty remains behind the isolated public-ABI boundary.

`scripts/native_grid_hot_session_smoke.sh` performs a fresh-process Wayland/X11 reconstruction of two customized tabs and five live panes, including recursive ratios, titles/colors/tags/Smart Tab/profile/settings/cwd, then proves malformed-file fallback.

`scripts/native_grid_profile_preset_smoke.sh` opens pane 2's real five-item `Profile` submenu while pane 1 owns keyboard focus, confirms the current item, then drives Readable, High contrast, and Mono no ligatures. It requires 14 pt geometry, rendered high contrast, live ligature-preference delivery, exact-target isolation, dirty state, and snapshot/autosave restoration; its repeated matrix reports `native_grid_profile_preset_matrix wayland=true x11=true exact_target=true isolated=true persisted=true restored=true`.

`scripts/native_grid_terminal_chords_smoke.sh` runs two live panes with broadcast enabled on Wayland and X11. It drives the real GTK key path, requires exactly one ETX on the focused pane and zero on its neighbor, then requires exact-pane `Ctrl+D` model/PTY/GTK teardown, zero forwarded EOT bytes, surviving focus, and final-pane protection.

`scripts/native_grid_tab_reorder_smoke.sh` launches an owned X11 NOCTTY window, validates its PID, and uses real pointer press/move/drop input to move background tab 1 after tabs 2 and 3. From a Wayland desktop it uses a disposable Xvfb + `kwin_x11` session when those existing host tools are available, avoiding unreliable Xwayland focus automation. It requires GTK order, Zig stable-ID order, preserved tab-3 activity, coalesced persistence, snapshot/reload order plus active identity, and clean exit. Wayland uses the same GTK notebook path; consent-free synthetic Wayland pointer injection is not claimed by this X11 gate.

`scripts/native_grid_compact_ux_smoke.sh` renders and exercises the palette, scrollback search/save, quick-note writeback, transient assistive names, pane zoom/restore including tab-row hide/restore, directional focus, pane-local Ctrl+wheel increase/decrease, neighboring-pane isolation, ordinary wheel preservation, workspace font-profile reload, standard OSC notification attention, IM context, same-directory split, and transient chrome. `scripts/native_grid_note_overlay_smoke.sh` renders a multiline UTF-8 workspace note over two mapped panes on Wayland and X11, requires compact bounds on every pane, then proves Alt release hides all copies. `scripts/native_grid_tab_navigation_smoke.sh` creates two tabs and a split on Wayland and X11, drives `Ctrl+Tab`, drives Alt+wheel down/up with rendered pane feedback, proves the other tab and a Smart Tab-hidden pane are never selected, drives Ctrl+Alt+wheel down/up with last-to-first wraparound and rendered tab feedback, drives `Ctrl+Shift+Tab` without losing the filter, and then rechecks PageUp/PageDown plus close/reopen focus restoration.
