# NoctEd

Last verified: 2026-08-03.

NoctEd is NOCTTY's standalone native project editor. It is built as the separate `nocted` executable, runs in its own process, and does not share NOCTTY's terminal lifetime. The implementation is Zig; `src/nocted/gtk.zig` is a narrow declaration-only GTK 3 and GtkSourceView 4 ABI boundary.

## Current Surface

The current desktop surface follows the compact Sublime Text 2 editing model:

- a persistent left project tree backed by a compact immutable arena index, with generated/vendor and bounded ignore rules applied, full scans and precise structural deltas processed on the background lane, and replacement snapshots published transactionally through bounded main-thread slices;
- reorderable file tabs with dirty markers, 28-logical-pixel width and 18-logical-pixel height close targets, 90% tab-label typography, hover/active/focus states, previous/next navigation, clean untitled buffers, native Save As, Save/Discard/Cancel-aware tab/close-other/close-all actions, and ordered active-tab restoration with dirty saved and untitled contents;
- line numbers, current-line highlighting, bracket matching, auto-indent, undo/redo, UTF-8 editing, and bounded select-all-occurrences transactions with rendered secondary ranges;
- bounded Sublime-style `Ctrl+wheel` editor zoom from 60% through 240% in 10% steps, shared across open documents while ordinary wheel scrolling and the minimap scale remain independent;
- a right-side GtkSourceMap minimap constrained independently from editor font sizing, with a translucent viewport that leaves minimap glyphs visible;
- native find with next/previous navigation and occurrence feedback;
- bounded streaming literal Find in Files with unsaved-buffer snapshots first, path/line/column previews, GTK backpressure, and click-to-open line activation;
- bounded smart-case/top-K project quick-open with deterministic path-aware ranking, coalesced query edits, and keyboard/row activation;
- persisted indentation-based code folding with current/all fold and unfold actions;
- GUI-owned Open Recent and Clear Recent Projects actions with bounded most-recent-first history;
- a compact menu strip and line/column/language status bar; a launch with no restored/open document creates one clean Untitled buffer and names Ctrl+S as the next save action;
- GUI toggles for the project tree, minimap, and code folding, persisted under `XDG_CONFIG_HOME/nocted` or `~/.config/nocted`.

NOCTTY's `Open NoctEd Here` action resolves the selected pane's live working directory and starts the sibling `nocted --project <directory>` process. Packaged installs and dependency bundles ship both binaries. NOCTTY does not reap, close, or retain NoctEd document state; NoctEd owns its own dirty-document prompts and remains open when NOCTTY exits.

## File Safety

- Files up to 1 MiB are editable. Valid UTF-8 files from 1 MiB through 8 MiB open as read-only previews. Larger, invalid UTF-8, or NUL-bearing files are rejected before a text buffer is published. Device, inode, size, and nanosecond mtime must agree before and after the read; a concurrent one-time rewrite retries to the current generation, while continuous churn fails after three attempts instead of attaching stale bytes to a newer identity.
- Open paths are canonicalized before document identity and writeback, so editing through a symlink updates its target instead of replacing the symlink.
- Existing saves replace files atomically and preserve permission bits. First saves create the selected file atomically without creating parent directories. Save As canonicalizes existing files and the selected parent directory before document identity changes, refuses a target already owned by another open buffer, adopts the path only after a successful write, and re-detects syntax from the new filename.
- Project scans stop at 100000 entries and depth 32, skip generated/vendor directories, apply bounded directory-scoped `.gitignore`/`.ignore` rules, and publish one immutable path arena plus offset entries. The background filesystem lane advances the scanner in bounded steps and checks cancellation between them. GTK constructs a staging tree in 128-entry main-thread slices; the prior model/index remain usable until commit. Coalesced `GFileMonitor` create/delete/move/rename batches are capped at 256, refresh only the precise path or directory subtree on the same background lane, and publish another immutable snapshot. Save As enters this route directly instead of forcing a full scan. Ignore-control mutations, malformed paths, unknown event kinds, and overflow deliberately request the bounded full scanner; content-only events continue to drive clean-reload or dirty-keep decisions for open files.
- Find in Files accepts one valid UTF-8 line up to 256 bytes. A generation-owned background job searches immutable unsaved-buffer snapshots first, then advances indexed disk files through reusable bounded chunks; it skips NUL-bearing or invalid UTF-8 data, keeps at most 1000 matching lines, and bounds previews to 240 UTF-8 bytes. Immutable batches of at most 24 results or 25 ms publish only on GTK's main thread, with no more than two unconsumed batches.
- Quick Open reuses the current project index and coalesces edits for 30 ms. Its valid UTF-8 query is capped at 256 bytes; directories are excluded, a smart-case subsequence gate removes non-candidates, and path-aware scoring retains at most 100 winners through fixed-size top-K selection.
- Folding analysis is single-pass and capped at 4096 regions with nesting depth 256. A fold applies a compact invisible text tag over the body while leaving every byte in the GtkSourceBuffer. It duplicates no document text, does not mark the file dirty, and preserves native undo history. Search, edits, undo/redo, and disabling folding remove the tags first; save always reads the complete buffer.
- Select All Occurrences accepts a nonempty valid UTF-8 selection of at most 4096 bytes and retains at most 256 normalized ranges. Secondary endpoints are gravity-aware GTK marks and a text tag; the native primary selection remains authoritative for clipboard and IME ownership. Typing, Backspace, and Delete replace ranges from the end backward inside one user action, so the complete transaction is one undo step. Escape or an unrelated edit clears secondary state.
- `settings.conf` and `session.conf` are versioned atomic files under NoctEd's configuration directory. Settings remains capped at 64 KiB and retains GUI-owned view/folding/syntax-path state. Session version 2 retains at most eight deduplicated recent projects and 32 ordered tabs, including active-tab identity and bounded dirty UTF-8 contents for saved or untitled buffers; version-1 saved-path sessions remain readable. Edit-pause snapshots are debounced for one second, graceful application exit writes immediately without prompting, and the private file is created with `0600` permissions. The session cap is 48 MiB, derived from the editor's 32 one-MiB editable-buffer ceiling plus base64/path metadata. Unsupported versions, duplicate/unknown fields, invalid base64/UTF-8, NULs, invalid indexes or path relationships, and oversized input fall back safely without masking allocation failures. An interrupted atomic replacement leaves the prior complete file intact. Individual dirty-tab closes still require Save, Discard, or Cancel. A failed hot-exit snapshot blocks application exit rather than discarding edits; forced termination can restore the last completed idle snapshot but cannot guarantee the newest sub-second edits.
- Desktop and file-association launches use one `GApplication` primary per user configuration. Secondary launches forward project/file paths to that process; a filesystem lock protects the session path when D-Bus registration is unavailable. Explicit opens restore the existing session before adding the requested paths, and display-independent smoke fixtures set `NOCTED_DISABLE_SINGLE_INSTANCE=1` with isolated XDG state.
- GtkSourceView undo retention is capped at 128 levels. Per-document search contexts and minimaps are created only when first shown, then explicitly released with the source buffer. Canonical paths use a hash map for document identity, notebook pages carry their document pointer, and project/search/quick-open models store bounded integer entry IDs rather than duplicate full paths.
- At most two lazy single-thread GLib lanes separate foreground document load/save/Save-As path work from background project scan/search work. The application caps outstanding jobs at 64, cancels obsolete generations before admission, copies immutable request data before submission, and transfers completed state through GTK's main context. Shutdown cancels jobs, joins both lanes, drains completions, removes monitors, and only then releases documents and widgets (`nocted_worker=bounded`, `nocted_worker_lanes=2`).

NoctEd performs no telemetry, update checks, crash upload, syntax download, plugin execution, or network access. It is an LSP client only and never implements language semantics or acts as an LSP server. Tools-menu actions start an installed local server on demand over bounded stdio JSON-RPC, send the active in-memory document, enforce an 8-second response timeout and 4 MiB message cap, answer server-to-client requests conservatively, and stop the process after the request. Diagnostics, selectable completion, hover, definition navigation, references, rename, document symbols, and formatting are available. Rename edits are restricted to the open project (or current file without a project), non-local edits are rejected, open buffers remain unsaved, and closed files are updated atomically. The display-independent installed-clangd probe retains `nocted_lsp_smoke client=true server=false transport=stdio framing=true initialize=true did_open=true symbols=true clangd=true timeout=true scratch_clean=true`. Tools also offers bounded Check/Build/Test/Run project tasks detected from `build.zig`, Flutter/Dart metadata, `package.json`, .NET projects, Python manifests, or Makefiles. Tasks run on the foreground worker with a 120-second limit, bounded output, cancellation supersession, and no shell evaluation (`nocted_task_smoke detected=true bounded=true background_worker=true output=true exit_status=true scratch_clean=true`).

## Syntax Definitions

NoctEd uses GtkSourceView XML `.lang` definitions, an established reusable syntax format available from Linux distributions and editor language-pack projects.

- The installed GtkSourceView 4 search paths are used automatically.
- A bundled Zig definition provides a stable baseline.
- On first launch, NoctEd compares GtkSourceView 3 user and system definitions with the GtkSourceView 4 baseline. It prompts to import only directories that add language definitions.
- `Tools > Import Syntax Definitions...` lets the user add a directory containing `.lang` files without editing the settings file. Up to 16 imported directories are retained.
- `Tools > Import TextMate JSON Grammar...` accepts bounded JSON TextMate grammars used by VS Code extensions, converts supported match/range/repository rules into a non-executing GtkSourceView definition, and activates the result without settings-file editing.
- TextMate input is capped at 1 MiB, 512 supported patterns, 4096 bytes per expression, 32 file types, and 16 repository-include levels. Empty, malformed, oversized, cyclic, missing-pattern, unsafe-extension, and unsupported-only grammars are rejected before installation.
- Converted definitions are atomically stored under NoctEd's configuration directory. A normalized scope name owns the output identity, so a later import of the same ID deliberately replaces the earlier generated definition; generated definitions precede bundled, GUI-imported, and system search paths. Runtime activation replaces the language manager before re-detecting open buffers because GtkSourceView does not permit changing an enumerated manager's search path.

The retained rendered baseline on this host discovers 171 installed definitions and 172 after importing the disposable TextMate grammar. GtkSourceView supplies broad installed fallback coverage for Dart, TypeScript/JavaScript/JSX/TSX, CSS/SCSS, HTML, JSON, CSV, TOML, Markdown, C/C++, C#, PowerShell, Python, Rust, Go, Java, Kotlin, PHP, SQL, YAML, and XML; NoctEd also bundles a Svelte fallback definition. Direct Tree-sitter remains intentionally limited to the bundled Zig, JSON, C, Bash, and Markdown adapters. Its 100 ms edit debounce accepts at most 32 KiB and 4,096 complete captures on GTK's main thread; larger or more capture-dense files switch visibly to GtkSourceView instead of applying a partial result. A focused one-off ReleaseFast repetitive-Zig probe measured parse-plus-capture p50 at about 5.9 ms for 32 KiB versus 43.5 ms for the former 256 KiB ceiling. JSON TextMate/VS Code grammar conversion is unit/source verified and passes warning-fatal X11 and Wayland activation. It intentionally does not parse plist `.tmLanguage`, YAML Sublime `.sublime-syntax`, VS Code extension manifests, injections, embedded-language maps, or arbitrary Oniguruma-only semantics.

## Launch

```sh
zig build run-nocted -- --project . --open src/nocted/main.zig
./zig-out/bin/nocted --project /path/to/project
./zig-out/bin/nocted file.zig another.json
./zig-out/bin/nocted # restore the last clean/dirty project-tab session
```

## Editing Controls

- `Ctrl+N`: create a clean untitled buffer.
- `Ctrl+S`: save the current document.
- `Ctrl+Shift+S`: open the native Save As chooser.
- `Ctrl+P`: open bounded project quick-open; typing filters, Enter opens the selected file, and Down moves focus into the result list.
- `Ctrl+F`, `F3`, `Shift+F3`: document find, next, and previous.
- `Ctrl+Shift+F`: open `Find > Find in Files...`; Enter runs the bounded worker-backed project search.
- `Ctrl+Shift+L`: select all occurrences of the current selection; type, Backspace, or Delete to edit every rendered range in one undo transaction, and press Escape to clear them.
- `Ctrl+PageUp`, `Ctrl+PageDown`: previous and next file tab.
- `Ctrl+wheel`: increase or decrease editor text zoom without changing the minimap scale.
- `Ctrl+W`: close the current file through the dirty-document guard.
- `Ctrl+Shift+[`, `Ctrl+Shift+]`: fold and unfold the current indentation region.
- `File > New File`, `File > Save As...`, `File > Quick Open...`, and `File > Open Recent` expose creation/opening workflows without requiring shortcuts.
- File and View menus expose close-other/close-all plus fold-all/unfold-all without requiring settings-file edits.

## Maturity Boundary

NCT-103 establishes the separate process, compact editing surface, safety limits, syntax reuse, package integration, and native rendered proof. NCT-104 adds bounded select-all-occurrences editing, recent projects, ordered active-tab restoration, and version-2 dirty-buffer hot exit; NCT-105 adds bounded JSON TextMate conversion and native activation proof. NCT-107/NCT-108 add folding, minimap legibility, bounded project search, and multi-file controls; NCT-114 adds untitled buffers, Save As, atomic first-save, and Quick Open; NCT-117/NCT-118 establish bounded asynchronous ownership and short resource qualification. NCT-106 closes deterministic recovery, mutation/race, core/worker, and sustained native-GUI stability for the one-host alpha boundary. NCT-121/NCT-122 close the immutable index, bounded monitoring/deltas, streaming search/backpressure, top-K Quick Open, scale qualification, and sustained cross-backend lifecycle/search/ranking tranches. These slices do not establish Sublime Text 2 or Zed parity. Arbitrary multi-caret placement, additional syntax formats, batch replace with preview/confirmation, guaranteed latest-keystroke recovery after forced termination, varied-project or multi-day stability, and broad editor parity remain outside the completed alpha evidence.

The [performance and algorithm research](PERFORMANCE_ALGORITHM_RESEARCH.md) defines the implemented NCT-121/NCT-122 architecture and the remaining evidence contract. GtkSourceView and GtkTextBuffer remain the production editing surface; a custom rope/piece tree and default Tree-sitter highlighting are deferred because they would duplicate or replace that authoritative model (`performance_algorithm_research=true`).
